# AI Synthetic Test: Project Facts

These are the shared facts about the fictional Knowledge Desk project. Do not invent missing implementation, metrics, incidents, or employment history.

1. The assistant answers questions over internal text documents. It is read-only: it has no action tools, email access, or database-write ability through model output. Users still need organization-scoped access to source passages.
2. Jordan owns the question endpoint and provider wrapper. Other engineers own authentication, the ingestion worker framework, vector-index configuration, and deployment.
3. Authentication middleware supplies a trusted `organization_id` and user identity. The endpoint does not use an organization ID from the request body to determine access.
4. `POST /questions` accepts a nonempty question of at most 1,000 characters. Invalid input receives 422. PostgreSQL retrieval is constrained by trusted `organization_id` **before** selecting the top 4 passages by similarity. Passage records include `chunk_id`, `document_id`, organization, title, and text.
5. An existing ingestion worker extracts text and creates 600-character chunks with 80-character overlap. These settings came from a senior engineer, not a controlled experiment. An existing embedding service creates stored vectors. Jordan can explain their broad purpose but did not implement the embedding model or index.
6. The prompt includes a system instruction to answer from supplied passages, cite their chunk IDs, and say that evidence is insufficient when necessary. Retrieved passages are placed in a separate delimited data section and described as untrusted content. No comprehensive prompt-injection evaluation has been completed.
7. Generation returns JSON with `answer`, `citation_ids`, and `insufficient_evidence`. Pydantic checks field types. The endpoint also checks that every citation ID belongs to the retrieved set for this request. It does **not** check whether each cited passage actually supports every generated claim.
8. An empty retrieval result returns an insufficient-evidence response without calling generation. No tuned similarity threshold exists; a nonempty top-4 result is not a guarantee of relevant evidence. Only active/current document versions are indexed by the existing worker; version-management implementation is owned by others.
9. The provider wrapper uses a 6-second timeout per attempt, at most 2 attempts, and a 250-ms delay before the second attempt. It retries timeouts, HTTP 429, and HTTP 503. It does not retry other 4xx responses or malformed successful output. Handling of `Retry-After` and ambiguous provider-side completion has not been implemented. There is no streaming.
10. Exhausted provider attempts return HTTP 503 with `MODEL_UNAVAILABLE`; malformed successful output returns 502 with `MODEL_RESPONSE_INVALID`. These failures are not represented as a successful empty answer or as a successful insufficient-evidence answer.
11. Logs include request ID, trusted organization ID, retrieval and generation duration, attempt count, provider status/error category, and retrieved chunk IDs. Logs do not contain credentials, full confidential prompts, full passage text, or complete user questions.
12. Pytest uses injected fake retrievers and fake provider clients. Tests cover invalid input, trusted organization filtering, no retrieved passages, timeouts with two-attempt maximum, malformed JSON, and out-of-set citation IDs. They do not establish factual correctness or real production retry behavior.
13. Jordan prepared 20 evaluation questions: 16 answerable from known documents and 4 intentionally unanswerable. Records include expected source document IDs, retrieved IDs, output, and manual notes. There is no consistent claim-support label, no measured overall accuracy improvement, and no held-out comparison of chunking or retrieval settings.
14. No measured token cost, request volume, P95 latency, production reliability rate, or confirmed production incident is supplied. API and provider behavior above are project facts, not newly executed observations in this test.
15. The JD states review and automated tests before merge. On-call schedules, incident support, salary, overtime, team size, and detailed mentoring arrangements are unknown.
